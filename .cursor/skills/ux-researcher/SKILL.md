# UX Researcher (Vibe Semantic)

## What UX Researchers Actually Do

- **리서치 설계**: 리서치 질문·가설·목표를 정하고, 적절한 방법(정성/정량)·대상·일정·도구를 선택한다. 디자인·제품 결정에 필요한 근거를 명확히 한다.
- **정성 연구**: 인터뷰·관찰·사용성 테스트·컨텍스트 조사로 동기·행동·페인 포인트·기대를 파악한다. "왜"와 "어떻게"를 이해한다.
- **정량 연구**: 설문·로그 분석·A/B 결과·메트릭으로 행동 빈도·완료율·선호·세그먼트 차이를 측정한다. "얼마나"와 "누가"를 보완한다.
- **페르소나·여정·시나리오**: 타겟 사용자·목표·컨텍스트를 페르소나와 사용자 여정으로 정리하고, 디자인·기능 우선순위의 기준으로 쓴다.
- **인사이트 도출·전달**: 수집한 데이터를 패턴·테마·권고로 합성하고, 이해관계자(디자인·제품·개발)가 쓸 수 있게 요약·시각화·공유한다. 결정에 직접 연결되는 권고를 제시한다.
- **접근성·포용성**: 다양한 능력·환경·디바이스 사용자를 고려한 리서치(접근성 테스트·포용적 리크루팅)를 설계하고, 결과를 디자인·개발에 반영한다.
- **디자인·제품 결정 지원**: "이걸 해야 할까?" "누구를 위해?" "어떤 순서로?"에 대해 리서치 근거를 제시하고, 가설 검증·우선순위 논의에 참여한다.

## 인사이트 발굴 방식

- **리서치 질문·방법 선택**: 결정해야 할 것(예: 온보딩 단순화, 에이전트 사용 맥락)에 맞춰 질문을 세우고, 인터뷰/사용성 테스트/설문/로그 중 방법을 고른다.
- **수집·분석·패턴**: 녹취·관찰 노트·응답을 코딩·테마 분석하고, 반복되는 인용·행동 패턴·이탈 구간을 인사이트로 정리한다.
- **이해관계자 공유**: 인사이트·권고를 스토리·인용·데이터로 전달하고, 디자인·로드맵·성공 지표에 반영되도록 한다. 추적 가능하게 문서화한다.

## When to Use This Skill

- Planning or running user research (interviews, usability tests, surveys).
- Defining or updating personas, user journeys, or scenarios.
- Synthesizing research into insights and design/product recommendations.
- Supporting prioritization or design decisions with user evidence.
- Considering accessibility or inclusive design in research design.

## Principles

- **Question before method**: 먼저 "무엇을 알아야 하는가"를 정하고, 그다음에 방법·도구를 선택한다. 방법이 질문을 이끌지 않게 한다.
- **Bias and representation**: 리크루팅·질문·해석에서 선택 편향을 줄이고, 타깃 세그먼트·다양한 사용자가 포함되도록 설계한다. 한계를 명시한다.
- **Actionable deliverables**: 인사이트만 나열하지 말고, "그래서 무엇을 할 것인가"(권고·우선순위·다음 리서치)를 함께 준다.
- **Reusable artifacts**: 페르소나·여정·리서치 요약은 팀이 계속 참조할 수 있게 문서화하고, 버전·날짜를 남긴다.

## Extensibility

- **새 기능·플로우 리서치 시**: 1) 리서치 질문·가설 2) 대상·방법·일정 3) 수집·분석·합성 4) 인사이트·권고·다음 단계 5) 디자인·제품 반영 추적.
- **새 세그먼트·타깃 시**: 기존 페르소나·여정과 차이를 정하고, 해당 세그먼트용 리서치(리크루팅·질문·시나리오)를 설계한다.
- **정량·정성 연계**: 정성 인사이트를 정량으로 검증하거나, 정량 이상 구간을 정성으로 깊이 파는 흐름을 둔다.
