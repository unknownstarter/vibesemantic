# 최근 7일/30일(range) 적용 기준 설계 — GA4 vs CSV(날짜 유무)

**작성일**: 2026-02-01  
**목적**: "최근 7일 / 최근 30일" 선택이 GA4·CSV(날짜 있음/없음)에 어떻게 적용되고, 분석 결과를 고객이 혼동 없이 이해하도록 어떻게 구분할지 정리.  
**협업 관점**: 데이터 사이언티스트, 데이터 엔지니어, 데이터 분석가.

---

## 1. 문제 정의

- **현재**: 7d/30d 토글이 항상 노출되고, Summary·리포트 생성 시 **GA4·CSV 모두** `_date_range_from_range(range)`로 계산한 start/end로 mart를 필터링함.
- **GA4**: "최근 7일/30일"은 **시간 기준 분석**에 자연스럽게 맞음.
- **CSV**:
  - **날짜 컬럼 있음**: 업로드한 CSV가 Date/날짜 등 시계열이면 "최근 7일/30일" 필터 적용 가능 → **기간 기준 분석**으로 일관되게 서술 가능.
  - **날짜 컬럼 없음**: 세그먼트·카테고리별 집계 등 **기간 기준이 없는 데이터**. Ingest 시 date는 placeholder(오늘)로 저장되므로, 7d/30d 필터를 걸어도 사실상 "전체 집계"가 나옴. 하지만 **리포트/채팅에서 "최근 7일 CSV"처럼 서술하면 고객이 오해**할 수 있음.
- **목표**: "기간 기준이 있는 분석"과 "기간 기준이 없는(집계) 분석"을 **명확히 구분**해서, 분석을 원하는 고객이 만족하도록 한다.

---

## 2. 데이터 엔지니어 관점

### 2.1 현재 동작

- **summary_builder**: `_date_range_from_range(range_value)` → `start_str`, `end_str` (오늘 기준 -7일/-30일).
- **GA4**: `mart_ga4_*` 조회 시 `.gte("date", start_str).lte("date", end_str)` 적용 → **의도대로 "최근 N일"**.
- **CSV**: `mart_csv_daily_metrics` 조회 시 동일하게 `.gte("date", start_str).lte("date", end_str)` 적용.
  - CSV에 **날짜 컬럼이 있으면**: mart의 date가 실제 업로드 날짜 범위이므로 7d/30d 필터가 의미 있음.
  - CSV에 **날짜 컬럼이 없으면**: Ingest 시 모든 행에 **placeholder date(오늘)** 저장 → 7d/30d 필터를 걸어도 "오늘"만 포함되므로 **실질적으로 전체 행**이 조회됨. 즉, "최근 7일"이라는 **의미는 없고**, 단지 mart 스키마상 date가 있어서 필터만 타는 상태.

### 2.2 "CSV에 날짜 차원이 있는지" 판별

- **source_mappings.date_column**: Probe/Confirm 시 결정. `null`이면 "날짜 컬럼 없음(집계 데이터)".
- **프로젝트 단위**: 한 프로젝트에 CSV 데이터셋이 여러 개일 수 있음. "CSV 기간 적용 가능 여부"는 **해당 프로젝트의 mart_csv_daily_metrics에 기여한 데이터셋들** 중 **하나라도 date_column이 있으면** "기간 적용 가능"으로 볼 수 있음.
- **제안**: Summary 빌드 시, 해당 project_id의 csv_datasets + source_mappings를 조회해, **모든 confirmed CSV 매핑의 date_column이 null인지** 확인. 전부 null이면 `csv_time_scope = "none"`, 하나라도 있으면 `csv_time_scope = range_value`(7d/30d).

### 2.3 마트/쿼리 변경 제안

- **옵션 A (최소 변경)**: 쿼리는 그대로 두고, **메타데이터만 추가**. `data_sources.csv.timeScope = "7d" | "30d" | "none"`. 리포트/프롬프트에서 이 값을 사용해 서술만 구분.
- **옵션 B**: CSV가 전부 "날짜 없음"일 때는 mart_csv_daily_metrics 조회 시 **date 조건 없이** project_id만으로 조회(전체 집계). 이렇게 하면 "오늘" placeholder에 의존하지 않고, 의도가 "기간 무관 집계"임이 쿼리에도 드러남. (구현 시 placeholder 저장 정책과 일관되게 유지.)

## 3. 데이터 분석가 관점

### 3.1 고객 기대 정리

- **기간 선택(7일/30일)을 한 경우**: "최근 7일/30일 동안의 **기간 기준 지표**"를 보고 싶다.
- **GA4만 있을 때**: "최근 7일 GA4 세션·채널·페이지" → 기대와 일치.
- **CSV만 있고 날짜 있음**: "최근 7일 CSV 트렌드(예: Sessions, Leads)" → 기대와 일치.
- **CSV만 있고 날짜 없음**: "최근 7일"이 **CSV에는 적용되지 않는다**는 것을 알고, "**업로드된 CSV 전체 집계(세그먼트/카테고리별)**"로 읽어야 함. 따라서 **리포트/채팅에서 섹션·문구를 나눠** "기간 기반"과 "집계(기간 무관)"를 구분해야 함.

### 3.2 리포트/채팅 구조 제안

- **기간 기반 분석**: "최근 7일(또는 30일) 기준"이라고 명시하고, GA4·CSV(날짜 있음) 데이터만 이 문맥으로 서술.
- **집계 데이터 분석(기간 무관)**: "아래는 **기간 기준이 없는 집계 데이터**입니다. 업로드된 CSV 전체를 기준으로 한 요약입니다." 같은 문구로 시작하고, CSV(날짜 없음) 메트릭만 이 섹션에서 서술.
- **혼합(GA4 + CSV 날짜 없음)**: 예시 구조  
  - **1. 기간 기반 분석 (최근 7일)**  
    - GA4 세션·채널·트렌드 등  
  - **2. 집계 데이터 분석 (기간 기준 없음)**  
    - CSV 세그먼트/메트릭 요약  
- **혼합(GA4 + CSV 날짜 있음)**:  
  - **1. 기간 기반 분석 (최근 7일)**  
    - GA4 + CSV 시계열 통합 인사이트  
  - 필요 시 "CSV 트렌드"처럼 출처만 구분.

## 4. 데이터 사이언티스트 관점

### 4.1 해석 일관성

- **시간 차원이 있는 데이터**와 **시간 차원이 없는 데이터**를 같은 문장에서 "최근 7일"로 엮어 서술하면, 고객이 "CSV도 최근 7일만 반영된 것"으로 오해할 수 있음.
- **원칙**: "기간 기준이 있는 지표"와 "기간 기준이 없는 지표"를 **같은 기준으로 섞어 해석하지 않고**, 서술 단위(섹션/문단)를 나누고 각각에 **기준(기간 vs 집계)**을 명시한다.

### 4.2 추세/비교 서술

- **기간 기반**: "전주 대비", "최근 7일 트렌드" 등은 GA4·CSV(날짜 있음)에만 사용.
- **집계 데이터**: "세그먼트별 비중", "카테고리별 합계" 등으로 서술하고, "기간 비교"는 하지 않는다고 명시하거나, "동일 업로드 데이터 내 비교"로 한정.

## 7. 요약

- **최근 7일/30일**: GA4에서는 항상 적용. CSV는 **날짜 컬럼이 있을 때만** "최근 N일"로 적용하고, **날짜가 없으면** 기간 기준이 아니므로 **분석 내용을 구분**해 뽑아야 함.
- **기준이 다르다**: "기간 기반"과 "집계(기간 무관)"를 같은 기준으로 섞지 않고, **메타데이터(timeScope)**로 구분하고, **리포트/채팅에서 섹션·문구로 명시**해 고객이 만족하도록 한다.
